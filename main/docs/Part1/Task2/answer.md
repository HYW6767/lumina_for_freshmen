3. 到底啥是 token？他跟大模型啥关系？为啥现在的大模型都用 token 计费？

token 是模型读写的最小单位，由分词器切分文本得到，而模型的每一层处理的都是 token 的向量表示，输出的是词表上下一个 token 的概率，由于推理的成本与 token 数近似正相关，因此使用 token 计费

4. tokenizer 又是啥？他是模型吗？他是干啥的？

Tokenizer 是分词器，其负责将输入切分成一个个 token 并映射成整数 ID，其没有参数，不在计算图中，不参与前向，也不接受梯度，因此不是模型参数部分，但是一个大语言模型无法脱离 Tokenizer，除了将文本转换成 token 以外，其也将模型输出的 token 翻译成我们能看懂的文本

5. embedding 又是啥？

Embedding 则将 Tokenizer 切分出的 token 转换成向量形式，使得其可以参与模型内部的运算

6. 你认为大模型和我们招新之前涉及到的模型有啥区别？

首先，我们之前做的模型是**先有任务，再有模型**即根据任务训练模型，而大模型是**先有模型，再有任务**大模型从诞生之初就不是为了解决单一任务，而是能适应多种多样的任务

其次，其交互方式也从固定输入输出变成了允许使用自然语言

并且，就参数量来看，大模型的参数量远多于我们之前训练的模型，当参数量到达一定规模时就会引起质变，各种能力会自行涌现

最后，大模型训练需要大量的算力，正常家用的电脑根本无法负担的起，而我们之前训练的模型家用电脑就可以训练

7. 什么是 Encoder？什么是 Decoder？什么是 Transformer？

Encoder，即编码器，是一个将输入序列转换成一组上下文向量的模块，与 Embedding 不同的的地方是，其输出的序列是带有上下文的（Embedding 只是将离散的文字输入转化为连续的向量，不带上下文）

Decoder 在训练时，整段目标句一次输入，靠掩码一次算出所有位置的预测，在推理时根据已有的上下文，将 token 逐个输出，相当于模型的嘴

Transformer 则是一种回避循环、转而完全依赖注意力机制来刻画输入与输出之间全局依赖的模型架构，目前被广泛应用于大模型领域，在 attention is all you need 中由 Encoder 和 Decoder 各六层堆叠而成，数据由 Encoder 流向 Decoder，最后再变成输出

8. 从架构层面谈谈你对 Transformer 的理解

Transformer 与其他架构不同，其完全用注意力机制替代循环结构，通过位置编码，给每个位置注入一个与位置相关的向量，使模型能区分先后顺序，从而解决架构对顺序不敏感的问题，同时，其使用多头自注意力，使其能够并行关注多个子空间，以较小的额外计算量换取多子空间的表达力，同时在训练时使用矩阵运算实现并行运算，这也使得其可以适配 GPU 的能力（多核并行运算），且由于同层并行的特点，Transformer 架构能一次性喂入大量 token，满足大规模训练的要求（在推理时是串行），于是绝大多数主流大模型都使用 Transformer 架构

10. 什么是下游任务？什么是任务头？什么是 backbone？

backbone，即骨干网络，负责将原始输入转化为特征

任务头则接在 backbone 之后，将特征映射成任务输出的模块

下游任务，即用模型解决的具体任务，如图像分类等

总的来说，backbone 和任务头是用来解决下游任务的，而 backbone 和任务头的关系如下
输入 → [backbone 特征] → [head 决策] → 输出
